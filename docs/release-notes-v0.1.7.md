# doc2md v0.1.7（2026-09-15）

> 本版**合并 v0.1.5 + v0.1.6 + v0.1.7 三批**（0.1.5 / 0.1.6 从未单独发版）。完整发布记录见 `docs/RELEASE.md` 的「## v0.1.7」节。

## 重点变化

### OCR 质量三修（v0.1.6）

- **显式设置 OCR 版面模式为「自动版面分析」** —— 根因：tesseract.js 的**隐式默认**是 `SINGLE_BLOCK`（把整页当成一块均匀文本），导致**图/公式旁的正文整段丢失**、**横拍的整页文档全篇乱码**。真机 4 张样张 + 产品路径实测：改为 AUTO 后同一张图探针命中 2/5 → **5/5**。
- **大图预缩放**：长边 > 1500px 的图先等比缩小再识别（**只缩不放**）—— 实测更准且**快 30–60%**（12.6MP 手机照片 6.7s → 4.1s）。
- **质量提示**：置信度偏低、或中文场景混入高比例非中文字符时，明确提示「可能存在版面或方向问题」。

### 方向重试（v0.1.7）

- 实测 tesseract 的自动版面分析**只认一个旋转方向**（顺时针转 90° 可读；逆时针转 90° 全篇乱码）。
- 现在：结果不理想时**自动顺时针旋转 90° 重试一次，取更好的那个**。
  **不加任何词典资产**（不加 10MB）；**只重试一次**；**成本只落在坏例上**（约 1.3–1.75×，好结果不重试）。

### 中文照片的字间空格（v0.1.5，真机发现的真实缺陷）

- 图片直传路径原先漏接「汉字间空格折叠」→ 中文照片会输出「湖南 新 晃 侗 族 自治 县」这类结果；现已与 PDF 扫描页路径一致。

### 工程侧（不易察觉但重要）

- 新增 `.gitattributes`（`* text=auto eol=lf`）：根治「检出即 CRLF、而 git 视为无差异」的**字节级陷阱**（该陷阱曾让入库产物与磁盘字节不一致）。
- `npm run metrics` 报告改为**跨平台可重复**（POSIX 路径 + 遍历序确定化）。

## 已知边界（如实标注，不承诺）

- OCR **不适用于**：**手写内容** · **照片里的表格结构**（值大多能读出，但不产出 GFM 表格）· **行内公式**（如 `C = ε·A/d`）· **示意图内部标注**
- 形近字偶有误识（如「覆盖」→「才盖」、「逆向」→「道向」）
- 手机端：**不推荐 Chrome**（其文件选择器在应用声明了 `accept` 时会丢掉「文件」入口，只能从相册选）；部分定制 Android 系统的 Chrome/Edge 同样无「文件」入口；部分定制 ROM 的文件选择器不支持多选
- **关键数字请核对原图**（实测个案：同一张样张 8 处数值全部识别错误）
