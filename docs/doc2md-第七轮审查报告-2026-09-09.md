## 二、本轮新发现（第七轮）——按严重度排序

### 2.1 【P2 观察】PDF 多栏文档同行混排 — `pdf.js` `runsToPageText`
**现象**：按 y 分组后行内按 x 排序——双栏（论文/杂志）PDF 同一水平线的左列与右列 run 会被串进同一行，输出形如「左列文本右列文本」交替穿插。
**影响**：多栏 PDF（学术论文常见）转换质量明显下降；单栏 PDF 不受影响。
**建议（v2）**：组内按 x 排序后，检测相邻 run 的 x 间隙 > 页面宽度/3 时切分为第二栏行（按栏分块），或按 x 空间聚类后再分行。改动集中在 `runsToPageText`，约 10 行。

### 2.2 【P2 观察】xlsx rels Target `../` 相对路径未归一化 — `xlsx.js` `xlsxWorkbookMap`
**现象**：`/^\/+/.replace` 只处理了绝对路径形态；`../worksheets/sheet1.xml`（OOXML 允许的相对路径形态，第三方工具生成时可见）会被拼成 `xl/../worksheets/sheet1.xml`，精确字符串匹配 zip 条目失败 → 抛错回退库路径。
**影响**：功能不错误（回退后按 name 读、不张冠李戴），但丢失自解析路径的流式/日期快/截断精度。
**建议**：加 `../` 展开归一化：`target.replace(/^(\.\.\/)+/, '')` 后按 `xl/` 相对路径拼接（OOXML 中 rels Target 恒相对于 `xl/`）。约 2-3 行。

### 2.3 【P3 观察】自定义 formatCode 含字母误判日期 — `xlsx.js` `parseStylesDateFormats`
**现象**：`/[ymdhs]/i` 判定自定义格式为日期——`0.00 "sec"`、`0 "mm"` 这类**带引号文本 + 字母**的格式会被误判为日期样式 → 数字被转成日期（错值）。
**影响**：低频（自定义数字格式带 m/d/y/h/s 字母且非日期语义的场景少见）；误判后果 = 错值（比漏判更糟——建议仅在生产半年内观察，暂不改）。
**建议**：判定前剥离引号内文本段（如 `stripQuoted`），或限定 `[ymd]` 组合必须同时出现（`y.*m || m.*d || d.*y`）。留作下轮候选。

### 2.4 【P3 观察】fragFor BR 片段死字段 — `html2md.js`
**现象**：BR 分支 push 仍带 `vStart/vEnd: null`——t12 弃用「可见字符」规则后该字段已无消费者（joinFrags 现只读 lead/trail）。
**影响**：无（死数据）。建议随手清理（t12 后的残留），非必需。

### 2.5 【P3 观察】runsToPageText 空格折叠影响代码缩进 — `pdf.js`
**现象**：`text.replace(/ {2,}/g, ' ')` 把连续空格折叠——PDF 里的 ASCII art/代码缩进会丢失。
**影响**：文本近似路径的已知权衡（与 getTextContent 时代一致）；代码类 PDF 请走 OCR 或原样保留。
**建议**：在 docs 已知限制中留档即可，不改。

### 2.6 【P3 观察】pdfPageRuns 未处理 TM 旋转/缩放 — `pdf.js`
**现象**：`cx/cy` 只取 `args[4]/[5]`（平移分量），旋转/缩放矩阵（竖排、倾斜文本）未计算 → 这类页面 run 定位可能错位。
**影响**：竖排/旋转 PDF 罕见；错位只影响空格规则判定，不产生硬错误。
**建议**：留档观察；如遇真实竖排 PDF 报告再处理。

### 2.7 【P4】A 标签内文 `[` 未转义 — `html2md.js` `fragFor`
`inner.replace(/\]/g,'\\]')` 只转义 `]`；`[` 在链接文本中语法无害，可不改。

### 2.8 【P4】quoteElToMd 多段引用使用裸 `>` 行 — `html2md.js`
`parts.forEach` 段间 push `'>'`（裸引用行）——CommonMark 更规范的是 `>` + 空行；多数渲染器（GFM）两者皆可。可选优化。
