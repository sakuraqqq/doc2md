# doc2md 大文件路径专项 · 验收判据与先红断言设计（2026-09-17）

> **性质**：**设计稿** —— 观察期内只写文档、不改代码。归属批次 = `docs/HANDOFF-主开发线.md` §8-**G**（复盘后第一批）。
> **上游依据**：backlog §2.5 **#8/#9/#10** · HANDOFF §3 **A9**（护栏内仍冻死 117 s）· **A10**（界面反馈分层）· **A11.6**（手机侧 ADB 实测峰值 12.63 GiB）。
> **一句话目标**：**解析到够 1000 行就停** —— 耗时与内存应与**被使用的数据量**相称（秒级 + MB 级），而不是与文件规模相称。

---

## 1. 问题陈述（全部有实测数据，不估算）

| 输入 | 路径 | 桌面耗时 | 手机耗时 | 手机峰值内存 | **产出** |
|---|---|---|---|---|---|
| `real-big.xlsx` 5 万行 / 773 KB | 快路径（xlsx-self） | **31 ms** | 秒出 | — | 1000 行 |
| `4-mid-large` 25 万行 / 35.9 MB | **库回退全量** | **78.7 s** | **286.8 s**（夸克；系统浏览器崩） | **12.63 GiB = 369× 文件** | 1000 行 |
| `3-big` 43.6 万行 / 47.4 MB | **库回退全量** | 59.4 s（真机 UI）/ 116.8 s（headless） | 三命运：43 s 完成 / 20 s 崩 / 磨 20 min 无果 | 同上量级 | **真机从未产出**（待澄清） |

⇒ **为 1000 行的输出，付了 25 万–43.6 万行的全量解析代价**（时间 × 内存 × 三种崩溃结局）。

## 2. 验收判据（D1–D6，逐条可测）

| 编号 | 判据 | 判据形式（怎么测） | 现状 | 目标 |
|---|---|---|---|---|
| **D1** | **产物逐字节不变** | 同一输入的 markdown 与改前**逐字节相同**（含首行截断注释） | — | ✅ 必须（否则不是"路径优化"而是"改口径"） |
| **D2** | **解析量上界**（主判据，需埋点） | 新增 `meta.scan = { bytes, rows }`；对 25 万与 43.6 万两档断言 `bytes ≤ 8 MB` **且两者差 ≤ 10%**（证明"与规模无关"） | 全量（≈ 168 MB / 291 MB XML） | ≤ 8 MB · 差 ≤ 10% |
| **D3** | **绝对耗时上界** | 桌面 headless（msedge）：25 万行件 **< 5 s**；43.6 万行件 **< 5 s**；`real-big` 保持 **< 3 s**（L4a 既有门槛不放宽） | 78.7 s / 116.8 s | 见左 |
| **D4** | **内存** | 桌面 `performance.measureUserAgentSpecificMemory()` 峰值 **< 200 MB**；手机 PSS 用**同一份 `4-mid-large`** 做修前/修后对照（降幅 ≥ 90%） | 手机 12.63 GiB | < 200 MB（桌面）· ≥ 90% 降幅（手机） |
| **D5** | **护栏语义** | `sharedStrings` > 4 MB **不再**等价于"回退库全量解析"：改为**按需解析**或**预检 + 二次确认** | 回退 → 全量 | 见左（与 A9 修法①同批） |
| **D6** | **负对照** | 切回旧实现 ⇒ **D2/D3/D4 至少两项必红**，记录在 `tests/CONTRACT.md` §7 | — | 必做 |

> **阈值初值来源**（可复核）：1000 行 × 行均 ~390 B ≈ **0.4 MB**，留 20× 余量 ⇒ 8 MB；耗时按"与 8 MB 相称"给 5 s（当前快路径 5 万行 = 31 ms，余量充足）。

## 3. 先红断言设计（契约层）

**落点**：新增 **契约组 Y「大文件路径」**（Y 未被占用；组 U/V/W/X 已用）。

| 断言 | 内容 | 先红/先绿 | 备注 |
|---|---|---|---|
| **Y1** | **D1 产物不变**：25 万行件的 markdown **逐字节** = 基线哈希（基线值在实现前固化，含首行截断注释） | **先绿守卫**（锁住"不许改口径"） | 基线哈希由本机生成后写死进断言 |
| **Y2** | **D2 解析量**：`meta.scan.bytes ≤ 8 MB` 且两档差 ≤ 10% | **先红**（现在无 `meta.scan`，且是全量） | **需拍板加字段**（见 §4-4） |
| **Y3** | **D3 耗时**：25 万 / 43.6 万两档均 < 5 s | **先红** | 与 Y2 互补：Y2 看"读了多少"，Y3 看"花了多久" |
| **Y4** | **D6 负对照**：手工切回旧实现（方法记录在 CONTRACT §7），确认 Y2/Y3 变红后还原 | 手工步骤 | 沿用既有负对照手法（如 `.tmp/mk-pdf-neg.mjs` 模式） |

⚠️ **纪律**：**先红提交 → 实现提交**（两条独立提交，便于回滚定位）；**改断言 = 改口径**，Y1 的基线哈希一旦定稿，只能改实现不能改断言。

**⚠️ 一条被我否掉的候选判据**：原本考虑"时间比值不变性"（`t(43.6万)/t(25万) ≤ 2`）—— 实测该比值现状 = 116.8/78.7 ≈ **1.48**，**全量解析下也接近线性**，故**该判据判别力不足**，改用 Y3 的**绝对阈值**。

## 4. 拍板点清单（做之前要你定）

1. **主判据**：选 **Y2 白盒（加 `meta.scan`）** 还是只靠 **Y3 黑盒绝对阈值**？（建议 Y2 为主 + Y3 兜底）
2. **阈值**：`scannedBytes ≤ 8 MB` / 桌面耗时 `< 5 s` / 桌面内存 `< 200 MB` —— 是否照此定稿？
3. **D5 护栏改法**：① 改**按需解析**（改动大、收益彻底）② 保留回退但**预检 + 二次确认**（改动小，与 A9/A10 同批）—— 建议 ② 先行、① 随后。
4. **是否允许为测试加 `meta.scan` 字段**：字段不进 markdown ⇒ **不改产物字节**；先例 = `meta.truncated` / `meta.backend` / `meta.assets`。若不允许，判别力退化为只能看耗时。
5. **验收环境**：桌面 headless（msedge）+ 手机 PSS 对照（复用手机侧 ADB 只读档位与上轮口径）。

---

## 5. 实施顺序建议（复盘后第一批）

1. **预检**（读 ZIP 中央目录估解压规模 —— 能力已有：`findEocd` / `zipEntry`）→ 接 **A10 L1** 提示条 + **A9** 二次确认；
2. **解析止损**（够 `XLSX_ROW_LIMIT`(1000) 行即停）—— **xlsx-self 与库回退两条路径都要改**（只改一条等于没治）；
3. **Worker 化**（可选，A7.3-#9）→ 真转圈 / 进度 / 可取消（A10 L2/L3）；
4. **手机侧 PSS 修前/修后对照**（口径见 D4；修前基线已由 2026-09-17 ADB 档固化）。

---

## 6. 明确不做（边界）

- **不提高行上限**（1000 → 更多）：那是**另一个口径**（输出规模），与移动端资源天花板直接冲突，须单独拍板；
- **不追"精确天花板阈值"**：A11.6 已证其**随当时可用内存浮动**（同一文件 43 s / 20 s 崩 / 20 min 无果三种命运）；
- **不在观察期内改代码**：本文档只是设计（v0.1.9 观察期至 09-19）。
