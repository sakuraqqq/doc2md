# 图片导出方案调研（GitHub 三大项目实证，2026-09-07）

> 议题：docx/文档转 Markdown 时，图片怎么导出——base64 内嵌 vs 抽取为文件+相对路径引用？
> 结论先行：**抽取为文件 + md 相对路径引用是行业共识**；base64 仅作"单文件自包含"的可选兜底。
> 本记录用途：① v0.1.2 实现依据（方案 A 已拍板）② 论文「国内外现状/对比」素材。

---

## 1. Pandoc（jgm/pandoc，46.2k ⭐）——官方机制：--extract-media

- 官方命令行：`pandoc --extract-media=assets` → 图片抽到目录，md 内相对路径引用：`![](assets/Pictures/<hash>.<ext>)`
- 维护者 jgm 亲自回复的 [Discussion #9594](https://github.com/jgm/pandoc/discussions/9594)：抽取路径语义（容器原始相对路径保留，可手动改 src 与 mediabag 条目前缀）
- → **"抽取 + 相对路径"是 Pandoc 的默认设计方向**，不是边缘功能。

## 2. mammoth.js（mwilliamson/mammoth.js，6.3k ⭐）——社区模板即抽取

- [Issue #237 "Save Images via Node API (easily)"](https://github.com/mwilliamson/mammoth.js/issues/237)：CLI 有 `--output-dir`；Node API 无官方 imageDir 参数，社区标准做法 =
  `mammoth.images.inline()` 回调：`element.read("base64")` → 写文件 → `return { src: 文件路径 }`
- 侧证：[haxcms:wordimport](https://github.com/haxtheweb/haxcms/issues/1052) `detect base64 <img> tags, convert source to file source`——"把 base64 转回文件源"是下游真实需求。
- → 我们的 convertImage 回调写法（`mammoth.images.imgElement()`）与社区模板同构，只是默认内嵌了——**方向上对齐即可**。

## 3. MarkItDown（microsoft/markitdown，179k ⭐）——微软官方立场：反对 base64！

- [Issue #58](https://github.com/microsoft/markitdown/issues/58)（2024）：
  - 微软成员 **afourney**：*"Should they be included inline as base64? **I would argue against this**, since it makes the text unsuitable for a variety of downstream applications like indexing, or use in llms"*（base64 会让文本不适合索引/喂 LLM 等下游应用）
  - 社区（zrh535，5 👍）：*"Save to disk and reference in Markdown"*——选项一
  - 后续：base64 保留作为选项加回（[#1140](https://github.com/microsoft/markitdown/pull/1140)），即"默认不放、可选放"
- → **微软官方认证 + 社区共识：抽取优先，base64 作为显式选项**——与 doc2md 方案 A 完全一致。

## 4. 对 doc2md 方案 A 的结论

| 项目 | 做法 | 与方案 A 一致性 |
|---|---|---|
| Pandoc | --extract-media=目录 + 相对路径 | 一致（默认抽取） |
| mammoth 社区 | inline 回调写文件 + 返回路径 | 一致（我们改默认行为） |
| MarkItDown | 反对 base64（下游索引/LLM 不适配）；base64 仅保留为选项 | **一致 + 微软官方站台** |

方案 A（阈值 0 = 全抽取 assets/，md 相对路径；导出 = 默认 zip（md+assets）+ 可选单文件 md（内嵌 base64））**与三大项目共识对齐**。

## 5. 论文可用引用（对比表素材）

> "现有主流工具对文档图片导出的处理：Pandoc 支持 --extract-media 抽取至目录并以相对路径引用；mammoth 默认内嵌 base64，社区普遍采用转换回调抽取方案；Microsoft MarkItDown 明确反对 base64 内嵌（其开发者指出内嵌会使文本不适配索引与 LLM 等下游应用），仅将其保留为可选模式。本工具采用"全量抽取 + 相对路径 + 显式单文件自包含选项"的方案，与上述共识一致，并针对车间场景（图片文件需随知识库归档、单文档可分发）做了两档导出。"
