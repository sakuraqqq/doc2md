## 1. 已确认的 Bug（按影响排序）

### 1.1 嵌套表格会把内层 `<tr>` 也选进来（P1）

**位置**：`src/html2md.js` → `tableToMd(table, ctx)`

**问题代码**：
```js
table.querySelectorAll('tr').forEach((tr) => { ... });
```

**现象**：单元格内再嵌套表格（Word 文档、富文本 HTML 中都会出现）时，`querySelectorAll` 是**全局**选择器，内层表格的 `<tr>` 也会被遍历 → 外层表格行数错乱、行内容被拆进错误位置。

**对比**：同函数内取单元格用了 `tr.querySelectorAll(':scope > th, :scope > td')`（限定直接子级，正确）——唯独 `tr` 漏了 `:scope`，属明显疏漏。

**修复建议**：
```js
const trs = table.querySelectorAll(':scope > thead > tr, :scope > tbody > tr, :scope > tfoot > tr, :scope > tr');
trs.forEach((tr) => { ... });
// 或退一步：table.querySelectorAll(':scope > tr, :scope > * > tr')
```

**回归用例建议**（加入 C 组）：
```html
<table>
  <tr><td>外A</td><td>外B</td></tr>
  <tr><td>
    <table><tr><td>内1</td></tr><tr><td>内2</td></tr></table>
  </td><td>外C</td></tr>
</table>
```
期望输出恰为 2 行 × 2 列的外层表格。

### 1.2 PDF 文本层“单词粘连”（P1）

**位置**：`src/pdf.js` → `pdfConvert` 中 `getTextContent` 的行组装

**问题代码**：
```js
line += item.str;
if (item.hasEOL) { lines.push(line); line = ''; }
```

**现象**：Word/PPT 导出的 PDF 里，单词间的“空格”常是**字间距（字形位移）**而非空格字符。直接拼接会把 `Hello world` 输出成 `Helloworld`、`This is a test` 输出成 `Thisisatest`——整段文本不可读，且**契约测试不会红**（断言只查 token 存在/页码）。

**修复建议**：利用 `TextItem` 的 `transform[4]`（x 坐标）与 `width` 判断间距：
```js
let prevX = null, prevW = 0;
for (const item of content.items) {
  if ('str' in item) {
    if (prevX !== null) {
      const gap = item.transform[4] - (prevX + prevW);
      if (gap > item.height / 3) line += ' ';
    }
    line += item.str;
    prevX = item.transform[4];
    prevW = item.width;
  }
}
```
（阈值可用 `item.height` 或固定经验值，先以真实样例标定；`tests/data/real-*` 里有现成真实 PDF 可回归。）

**回归用例建议**：用 `tests/data` 中的真实 Word 导出 PDF 快照断言输出含 `is a test` 连续串（当前会粘连失败）。

### 1.3 链接/图片 URL 未转义（P2）

**位置**：`src/html2md.js` → `fragFor` 的 `A`/`IMG` 分支

**问题代码**：
```js
out.push({ t: '[' + inner + '](' + href + ')', ... });
out.push({ t: '![' + alt + '](' + src + ')', ... });
```

**现象**：
- href/src 含 `)` → 链接被提前截断（如 `https://a.com/x(y)`）
- href 含空格（罕见但存在）→ 语法破损
- alt 含 `]` → `![alt]` 解析错位

**影响面**：`.html` 输入路径（用户拖入任意 HTML）比 mammoth 路径更易触发；mammoth 输出的 href 一般规范，属次影响。

**修复建议**：输出前对 href/src/alt 做 MD 目标转义：
```js
const escUrl = (u) => String(u).replace(/\(/g, '%28').replace(/\)/g, '%29').replace(/\s/g, '%20');
// alt 侧：alt.replace(/\]/g, '\\]')
```
顺手建议：`href` 过滤 `javascript:`/`vbscript:` 开头的（防下游渲染器误用；本工具只输出文本无执行风险，属纵深防御）。

**回归用例建议**：
```html
<a href="https://a.com/p(x)">链接</a>
<img src="https://a.com/a(b).png" alt="图]片">
```

### 1.4 `start="0"` 的有序列表被改成从 1 开始（P2）

**位置**：`src/html2md.js` → `listElToMd`

**问题代码**：
```js
let n = isOL ? (parseInt(listEl.getAttribute('start'), 10) || 1) : 1;
```

**现象**：`<ol start="0">` 合法且常见（法律条文、倒序清单），此处 `parseInt('0')` 返回 `0`，`0 || 1` 变成 `1` → 输出从 `1.` 开始。

**修复建议**：
```js
const s = parseInt(listEl.getAttribute('start'), 10);
let n = isOL ? (Number.isNaN(s) ? 1 : s) : 1;
```

**回归用例建议**：
```html
<ol start="0"><li>零</li><li>一</li></ol>
```
期望输出 `0. 零` / `1. 一`。

### 1.5 代码块内三反引号破坏围栏（P2）

**位置**：`src/html2md.js` → `blockOfEl` 的 `PRE` 分支

**问题代码**：
```js
return ['```\n' + el.textContent.replace(/^\n|\n$/g, '') + '\n```'];
```

**现象**：代码本身含 `` ``` `` 时，输出 Markdown 的代码围栏被提前闭合，后续内容漂移成正文。

**修复建议**（动态围栏，改动小）：
```js
const body = el.textContent.replace(/^\n|\n$/g, '');
const fence = '`'.repeat(Math.max(3, Math.max(...(body.match(/`+/g) || ['``']).map(s => s.length)) + 1));
return [fence + '\n' + body + '\n' + fence];
```
或至少在接受输出里用 4 反引号并提示。

### 1.6 OMML 缺 `m:e` 时公式内容重复（P2）

**位置**：`src/docx.js` → `ommlParts`（`sSup`/`sSub`/`sSubSup`/`rad` 分支）

**问题代码**：
```js
const base = ommlChild(el, 'e') || el;   // 缺 m:e 时 base 退化为整个元素
parts.push(ommlConcat(base) + '^{' + ... + '}');
```

**现象**：若 `<m:sSup>` 内缺 `<m:e>`（结构异常或第三方工具生成），`ommlConcat(el)` 会把 `m:sup` 的内容也当作 base 输出一遍 → 公式文字重复（如 `x^{x^{2}}` 变味）。

**概率**：正常 Office 生成的 OOXML 都有 `m:e`，属低频防御；但一行可修。

**修复建议**：
```js
const base = ommlChild(el, 'e');
const baseT = base ? ommlConcat(base) : '';
parts.push(baseT + '^{' + (sup ? ommlConcat(sup) : '') + '}');
```
（`rad` 的 `ommlConcat(e || el)` 同款问题一并处理。）

### 1.7 下载文件名对 `.env` 类文件变成空（P2）

**位置**：`src/ui.js` → `downloadMd` / `downloadZip`

**问题代码**：
```js
const base = (fileName || 'doc2md').replace(/\.[^.]+$/, '');
```

**现象**：`file.name` 为 `.env`、`.gitignore` 等“扩展名即整个名”的文件时，`replace` 把 `.env` 整个吃掉 → base 为空 → 下载名为 `.md` / `.zip`。

**修复建议**：
```js
const base = ((fileName || 'doc2md').replace(/\.[^.]+$/, '') || 'doc2md');
```

## 2. 优化建议（按价值排序）

### 2.1 转换取消功能（体验，最高价值）
当前大 PDF（50MB + 多页 OCR）转换不可中断，用户只能干等。建议：页循环/字节循环里检查取消标志（UI 增加“取消”按钮），OCR 阶段支持提前停止（`worker.terminate()` + 重新懒加载）。

### 2.2 防止转换期间重复触发
转换进行中再次拖入文件会并发转换，`setStatus` 互相覆盖、手动内存飙升。建议：转换期间 `dropzone`/`fileInput` 置 `disabled` + 显示“转换中…”，完成后再恢复。

### 2.3 OCR 页内存优化
`src/pdf.js` `ocrPageToText` 固定 `scale: 2`：A4 双倍分辨率 canvas ≈ 35MB/页（RGBA），连续 OCR 数十页有内存压力。建议：按页尺寸降级（>1500px 宽时用 1.5），`canvas.width = 0` 主动释放，或识别完成即 `canvas.remove()`（现在每页新建、GC 兜底，可显式化）。

### 2.4 多文件并行（可选）
`app.js` `handleFiles` 纯串行：大文件排队期间小文件也等。可并发 2（注意 tesseract worker 单例，OCR 类文件仍建议串行）；或至少 UI 显示“第 x/y 个”。

### 2.5 测试边界补漏（下次发版必做）
建议为 1.1–1.6 各加一条用例（嵌套表格 / PDF 粘连 / URL 转义 / `start=0` / 三反引号 / OMML 缺 e）。当前契约测试（C 组/M 组）大概率全绿却测不出这些问题——它们属于“格式精确性”，建议加**快照式断言**（输出全文比对），不只看 token 存在。

### 2.6 构建一致性检查
`index.html`（81KB 含应用逻辑）与 `src/`（t8 模块化）并存，建议 `tools/build.mjs` 增加“src 变更 → index.html 重生成”的 CI 检查（或校验构建产物的 hash 锚点），防止只改 `src/` 忘记构建、线上跑旧逻辑。

### 2.7 SW 首装体积（保持即可）
precache 含 2×4MB wasm + 7MB traineddata，首次安装拉取大——已有 T-1 首载豁免设计，保持现状即可，本次不动。

## 3. 已验证的亮点（避免重复修复）

- **`sniff.js`**：魔术字节嗅探 + GBK/GB18030 兜底 + BOM 优先 + 二进制启发式，逻辑严密，未发现问题。
- **`decodeText`**：UTF-16BE 的浏览器解码 + 字节交换兜底、`fatal:false` 容错，正确。
- **`convert.js`**：50MB 护栏、注册表、错误隔离（单文件失败不影响批次）、`truncated`/`assets` 契约落地，干净。
- **`app.js` / `ui.js`**：live FileList 快照化（已修 A 线遗留 bug）、拖放 document 级拦截、SW 注册失败静默，规范。
- **`docx.js`**：OMML 占位令牌法保证公式顺序 + 图片阈值抽取（≤100KB 内嵌 />100KB assets）+ `fflate` 内联重打包，设计优秀；`isConnected` 防重复处理 `oMathPara` 也正确。
- **零外发红线**：`bline.js` 的 `importScripts` 拦截 patch（外域 URL 抛错）+ `corePath` 同源化，确认到位。
- **t12 规范**：扁平 if、线性正则（meta charset 解析用 indexOf 手工扫描）、Promise 级 `.catch` 不吞异常，全部合规。

## 4. 建议处理顺序

| 优先级 | 事项 | 工作量 |
|---|---|---|
| **本版修** | 1.1 嵌套表格、1.2 PDF 粘连 | 各约 5-10 行 + 1 条用例 |
| **顺手修** | 1.3–1.7 | 每条 1-3 行 + 用例 |
| **观察** | 1.8 XLSX 实体 | 低 |
| **下版做** | 2.1 取消、2.2 防重复、2.3 OCR 内存 | 中大 |
| **配套** | 2.5 快照式断言、2.6 构建一致性 CI | 中 |

**一句话结论**：核心转换链路（docx OMML / xlsx 截断 / OCR 降级 / 零外发）经得起推敲，剩余问题集中在两类——**富文本边界**（嵌套表格、URL 转义、围栏、start=0，都在 `html2md.js`）和**PDF 文本层质量**（间距粘连），修复成本低、收益直接。
