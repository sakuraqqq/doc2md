### 坑 / 根因 / 防再犯

**坑 1｜"判据"与"施工清单"粒度不一致 ⇒ 阶段 A 漏收口（本卡真实发生）**
- **现象**：卡面 A1 判据 = 全局 `grep "R9-1"`「**无一处**列为待做」；前序会话按台账《回填文本·四条》的 **4 条锚点**施工 ⇒ 判据命令仍命中 A8 backlog 表状态列（`待实现转绿`）与 §3.5 范例行（"待办里最典型的两条"）。
- **根因**：**同一个事实写在两处**（§8 排期栏 + A8 表状态列），施工清单只覆盖其一；核对判据与施工清单**粒度不同**时，"按清单做完" ≠ "判据通过"。
- **防再犯**：① 状态类事实**只留一处权威写法**，另一处**指路**（本卡已让两处互相引用）；② 收尾**先跑卡面判据命令**，再逐条对施工清单；③ 判据与清单粒度不同的卡，**接卡时就回问**（本卡判据明确，故直接补齐并如实登记）。

**坑 2｜负例"报了错，但报错原因不对"（守卫差点假绿）**
- **现象**：`guard-selftest` 首跑 **14/16**；两条 baseline 负例的 errors 只有 `released.tag 无法解析：v0.1.9`。
- **根因**：`loadActual(data)` 的数据源必须是**未篡改的 JSON**，我写成 `loadActual()` 无参 ⇒ `actual.released = null` ⇒ 断言"见到错"了，但错的是**接线**而不是**篡改**。
- **防再犯**：负例断言一律匹配**预期错误文本**（`expect` 正则），**禁止**只断言 `errors.length > 0` —— 否则接线 bug 会被当成"守卫有效"。（本例正因匹配了预期文本才暴露。）

**坑 3｜lint 绿 ≠ metrics 绿（两套复杂度实现）**
- **现象**：`npm run lint` exit 0（0 错 0 警）的同时，`npm run metrics` 首跑报 **超限 1**：`tools/baseline-check.mjs:225 checkDelivery cyc=12 cog=19`。
- **根因**：eslint `complexity`（阈值 10，warn）与 `tools/metrics.mjs` 的**近似认知复杂度**（阈值同、算法不同）**不等价**。
- **防再犯**：改 `tools/**` 后**必须跑 `npm run metrics`**（硬门禁，超限即 exit 1），不能只看 lint；另注意两条会直接报 error 的 sonarjs 规则：`no-os-command-from-path`（`execFileSync('git')` ⇒ 需带理由的 disable）与 `no-nested-assignment`（`(i += 1)` 内联自增）。

**坑 4｜沙箱禁「管道 stdio」⇒ node 里取子进程输出一律 `EPERM`（本轮第三次撞）**
- **现象**：① `execFileSync('git', …, {encoding:'utf8'})` → `Error: spawnSync git EPERM`；② `tools/metrics.mjs` 的 jscpd 子进程被拒 ⇒ 只能写出「重复率 **N/A**」（**入库版本正带着这个 N/A**）；③ `gh run view --log` 因 gh 缓存目录在工作区外被拒。
- **根因**：受限模式**不禁止 spawn**，只禁止**建管道**（`stdio: 'pipe'`）；`inherit` / `ignore` 与**文件描述符重定向**都可用。
- **防再犯**：需要子进程输出时用 `fs.openSync(tmp,'w')` + `stdio: ['ignore', fd, 'inherit']` **落文件再读**（已写进 `tools/baseline-check.mjs` 头注释，本会话实测可用）；跑 jscpd / 契约这类"要管道"的门禁则走**一次性升权**或 Linux 侧。
