## 0. 一句话

## ③ 清单来源：模型清单从哪来、主包怎么"发现"

### 结论（本设计建议 · 待拍）

**清单 = 一份签名 JSON，作为 GitHub Release 的资产发布**；主包在 **opt-in 开启后**按**固定 URL** 取「最新清单」→ **验签** → 缓存 → 作为「可用模型表」。
⭐ 两条守卫：① 清单**只是数据**（⛔ 不携带可执行内容）② **内置一份兜底清单**（离线 / 首次联网失败时，界面仍能说明有哪些模型可选）。

### 依据

- **model-spec（OCI 制品）**：业界把"模型 = 清单 + 配置 + 权重层"写成规范，且**描述与数据分离、按摘要寻址** ⇒ 我们照此**裁剪**（见调研件 §2.1）。
- **Obtainium**：Android 上"用户自己填来源 + 自动更新"有人真这么做且活跃 ⇒ "从源头取"的现实性成立（调研件 §1 第 4 条）。
- `I2` 已把服务器定成 GitHub Releases ⇒ 无需自建 registry。

### 候选与代价

| 候选 | 形状 | 代价 |
|---|---|---|
| **A（推荐）远端签名清单 + 内置兜底** | 取 `latest` 清单，验签后缓存 | 需实现"清单缓存 / 过期 / 取不到时用兜底"三条分支；URL 若变更需发版或重定向 |
| **B 仅内置静态清单** | 新模型 = 发新 APK | **零联网面**（最安全）但**模型更新绑死发版节奏**；⭐ 它天然是 A 的**降级档**（可作为"离线模式"形态保留） |
| **C OCI 制品式（digest 寻址 + registry）** | 按摘要拉层 | 要 registry 与 OCI 客户端逻辑；对 `I2`（GitHub Releases）**过度设计** |

### 待拍点

1. **清单域**：GitHub 直连（`api.github.com` / `raw`）还是经**自建 Pages 中转**？（影响 ③ 的可用性与隐私面）
2. **"不发版能否上新模型"**的边界：允许到哪一步（换模型 / 换能力档 / 仅换版本）？
3. 兜底清单的**更新责任**（谁保证它与远端差距不至于误导用户）。

## ④ 更新策略：怎么更新、怎么回退、怎么不把它弄坏

### 结论（本设计建议 · 待拍）

**显式版本 + 只前进 + 原子替换 + 失败保旧**；**用户显式"退回上一版"是独立通道**（需告知风险）。
四条硬规则（**负面验收面**，照 TUF 的攻击清单裁剪 —— 见调研件 §2.2）：

- **拒绝更旧**：清单项 `version` 低于本地已装版本 ⇒ 拒绝（防**回滚**）。
- **单调交叉校验**：清单带单调序号或 `publishedAt`，与 `version` **交叉校验**（防 **fast-forward**：把版本号吹到未来）。
- **撤销可达**：清单可标 `revoked`；已撤销的模型**不再"可用"**，客户端要提示（防"已知坏模型继续被用"）。
- **失败可见**：取不到清单 / 验签不过 / 下载失败 —— **每一条都必须有一条用户看得见的说明**（防**无限冻结**的"静默停在旧版"）。

### 依据

- **TUF 规范**把更新系统的攻击面列成可验收目标：回滚 · fast-forward · 无限冻结 · 混搭 · 装错软件 · 单钥失陷 —— ⭐ 上文四条规则正是其中与"单产品单清单"相关的裁剪（调研件 §2.2）。
- **Android 官方**：缓存目录可能被系统清 ⇒ "更新失败保旧"必须**真的不动旧版本**（§⑤ 的存放语义）。

### 候选与代价

| 候选 | 形状 | 代价 |
|---|---|---|
| **A（推荐）只前进 + 用户可见的"检查更新"** | 默认不自动下载；用户点"检查"→ 提示可更新 | 新鲜度靠用户主动；但**最省流量、最符合 opt-in** |
| **B 通道制（stable / beta）** | 两套清单或清单内标通道 | 多一份状态与 UI；⚠️ 需先拍"beta 数据是否与 stable 混用" |
| **C 静默后台自动更新** | 有网即拉 | ⚠️ **撞 `I7` 的 opt-in**（"不得设计成不读就会点同意"）+ 流量/电量不可控 ⇒ 本设计**不采纳**，但**保留开关**（默认关） |

### 待拍点

1. **"已过期"的判据**：只比版本号，还是以 `revoked` / "不向前兼容"标记为准？
2. **回退是否允许**：默认拒绝（TUF 立场）；但"用户想退回上一版"是真实诉求 ⇒ 是否需要"**显式回退通道 + 风险告知 + 留痕**"。
3. **检查更新的时机**：仅用户手动 / 打开 App 时（可关）/ 定时（不建议）。

## ⑤ 配额与清理：下到哪、被系统清了怎么办

### 结论（本设计建议 · 待拍）

- **权重放"应用专属持久目录"**（Android `filesDir` 语义），⛔ **不放缓存目录**；
- **可重建的东西**（清单副本 / ETag / 上一次校验结果）放**缓存目录**（丢了能重建）；
- **下载前先查可用空间 + 配额**；**下载后核对 `size`**；
- **总量上限 + 超限时提示用户清理**（⛔ **不静默删**）；**卸载即清**是系统保证（可依赖）。

### 依据（Android 官方「访问应用专属文件」，逐条对应）

| 官方事实（读到正文） | 对我们的判定 |
|---|---|
| 应用专属空间分**持久**（`filesDir`）与**缓存**（`cacheDir`）两目录 | 权重进**持久**目录 |
| ⚠️ **内部空间不足时，系统可能删除缓存文件** | ⛔ **权重绝不能放缓存目录**（否则被静默清掉 = 卡面 ⑤ 要治的病） |
| 可查 `getCacheQuotaBytes()`；官方明写"**你也不应依赖系统替你清缓存**" | 上限与清理**由我们自己管** |
| **卸载应用 ⇒ 系统移除应用专属文件** | "已删除"态可由系统触发，UI 不必假装文件还在 |
| 内部空间"通常比较小"，写前**先查询可用空间** | 下载前**预检**是必需项，不是优化 |

### 候选与代价

| 候选 | 形状 | 代价 |
|---|---|---|
| **A（推荐）单档上限 + 超限提示清理** | 例：总占用 ≤ N MB；超限时列占用并给"删除某个模型"入口 | 需定 N；需做占用统计 UI |
| **B 按设备可用空间动态分档** | 按剩余空间决定允许装几个 | 判定复杂、可解释性差；⚠️ 要拍阈值表 |
| **C 不设上限（装不下就报错）** | 最省事 | ⛔ **撞 `I4` 第 4 条**（硬上限 + 主动降级）⇒ 不采纳 |

### 待拍点

1. **上限取值**（与 `B2` 档位、随包 4.8 MB 的现状对齐）；
2. **超限行为**：拒绝下载 / 提示清理后重试 / 允许用户先删别的模型；
3. 是否需要"**仅本次使用、用完即删**"的临时档（对低存储设备友好，但要额外状态）。

## 4. 模型清单（manifest）字段表

⭐ 每个字段都给六件事：**名称 / 类型 / 谁填 / 谁验 / 被篡改会怎样 / 缺失时行为**。
（"谁填" = 发布方；"谁验" = 客户端）

| 字段 | 类型 | 谁填 | 谁验 | 被篡改会怎样 | 缺失时行为 |
|---|---|---|---|---|---|
| `id` | string（稳定标识） | 发布方 | 客户端（格式 + 白名单） | 指向另一个模型 ⇒ **装错模型**（TUF 的 "wrong software installation"） | 该条**不可用**（整条跳过） |
| `capability` | enum（如 `table-structure` / `layout` / `postprocess` / `decision`） | 发布方 | 客户端（**只接受自己支持的能力名**） | 能力错配 ⇒ 调错接口 / 崩 | 该条不可用 |
| `version` | string（或整数序号） | 发布方 | 客户端（**单调性检查**） | **回滚**（诱导装更旧） | **整份清单不可用**（⛔ 不做"缺字段就放行"） |
| `size` | 整数（字节） | 发布方 | 客户端（下载前预检 + 下载后核对） | 空间误判 ⇒ 下到一半失败 | 该条不可用（⛔ 不许"未知大小也照下"） |
| `sha256` | hex（64） | 发布方 | 客户端（**下载后必校**） | 换成被替换的权重 ⇒ 执行不可信模型 | 该条不可用 |
| `signature` | base64（**对清单**的签名） | 发布方（私钥） | 客户端（**清单级验签**） | 伪造整份清单 ⇒ 可发任意条目 | **整份清单不可用**（⛔ **不降级为"不验签继续"**） |
| `minAppVersion` | string（与主包版本同格式） | 发布方 | 客户端（版本比较） | 诱导旧主包加载新格式 ⇒ 崩 | 该条不可用，并提示"请更新 App" |
| `license` | string（SPDX 标识） | 发布方 | 客户端（**`I3` 白名单**：`MIT`/`Apache-2.0`/`BSD`） | 换成没授权的许可 ⇒ 合规风险 | 该条不可用（⛔ 无许可 = 默认不可用） |
| `url` | https URL | 发布方 | 客户端（**必须 https + 域白名单**，`I7`②） | 指向恶意源 ⇒ 下载被劫持 | 该条不可用 |
| ⭐ **建议补** `publishedAt` / `seq` | ISO 日期 / 单调整数 | 发布方 | 客户端（与 `version` **交叉校验**） | **fast-forward**（版本号吹到未来，使后续更新永远"像回滚"） | 缺 `seq` ⇒ 退化为"仅比 `version`"，并在清单级降级登记 |
| ⭐ **建议补** `revoked` | bool 或时间戳 | 发布方 | 客户端（撤销检查） | 让已撤销的模型仍可装 ⇒ 已知坏模型继续被用 | 缺失 = **未撤销**（默认放行，但见下 ⚠️） |
| ⭐ **建议补** `runtime` | object（框架 + 精度 + 输入形状） | 发布方 | 客户端（是否支持该框架/精度） | 加载不兼容的权重 ⇒ 加载失败（可降级） | 该条不可用 |

⚠️ **`revoked` 的一个诚实缺口（必须登记）**：撤销**只在能取到更新清单时生效** —— **离线用户取不到撤销** ⇒ 这是 TUF 的"无限冻结"问题在我们这种**单清单单产品**裁剪下的残留风险。**缓解**：把"清单多久没更新过"显示给用户（⛔ 不假装撤销一定能到达）。

## 5. 生命周期状态机

### 5.1 状态与允许的迁移

| 状态 | 含义 | 允许迁往 | 失败分支 | 回滚 |
|---|---|---|---|---|
| **未安装** | 本地无该模型（可能是内置兜底清单里的一条） | → 下载中 | 无 | 不适用 |
| **下载中** | 正在写**临时文件**（`.part`），**不碰**已装版本 | → 已校验 / 未安装 | 断网 / 超时 / 取消 / 空间不足 | 保留旧版本（若有）；删 `.part` 或留作续传 |
| **已校验** | `size` + `sha256` + 签名**三项通过** | → 可用 | 验签不过 / 摘要不符 | 删临时文件 ⇒ 回到未安装 / 旧版本仍可用 |
| **可用** | 已**原子改名**进持久目录，并写好"当前版本指针" | → 更新中 / 已过期 / 已删除 | 改名失败（空间/权限） | **指针不动** ⇒ 旧版本继续可用 |
| **更新中** | 新版本走"下载中 → 已校验"全程 | → 可用（切指针）/ 可用（保持旧版） | 任一环失败 | **指针不动**（旧版本继续可用） |
| **已过期** | 被 `revoked`，或版本落后于清单且已提示 | → 更新中 / 已删除 | —— | 若上一版仍在本地 ⇒ 允许**显式**退回（见 §④ 待拍点 2） |
| **已删除** | 用户主动删 / 卸载（系统清） | → 未安装 | —— | 重新下载 |

⭐ **两条不变量**：① **已装好的版本在"更新成功"之前绝不被改动**（原子替换 + 指针）；② **任何失败都要有一条可见说明**（⛔ 不静默）。

### 5.2 四类失败的处置（卡面点名）

| 失败 | 检测点 | 处置 | ⛔ 不许 |
|---|---|---|---|
| **下载中断网** | 传输层错误 / 超时 | 保留 `.part` 支持续传（HTTP Range）；重试有上限；**状态栏 + 卡片内提示** | 静默重试到天荒地老；把半包当完整包 |
| **验签失败** | 清单级 / 权重级 | **立即丢弃该次下载**；报错可见；**记录失败计数**（防降级攻击反复试探） | ⛔ **"忽略签名继续"**（这是最诱人也最危险的降级） |
| **存储不足** | 下载前预检 + 写入时二次捕获 | 拒绝下载 + 给出"当前占用 / 可释放"信息与清理入口 | 下到一半才报错；静默删除别的模型腾空间 |
| **版本回退** | 清单版本比较 | **默认拒绝**（防回滚）；用户显式回退走**独立通道**（告知风险 + 留痕） | 把"拒绝回滚"写成"永远不能退" —— 要保留用户通道 |

## 6. `I4` 六条机制的落点

⭐ 每条一行；标签即落点编号（供 verify 机器计数）。

| 标签 | 机制（`I4` 原文） | 本设计落点 |
|---|---|---|
| `B2-1` | **体积明示** | 清单 `size` 字段（§4）+ 下载前"将占用 X MB"确认 + 设置页"当前占用"汇总（§⑤） |
| `B2-2` | **显式同意（opt-in）** | 默认关闭；开启与关闭**路径等长**（`I7`③）；开关文案**明说"这是在绕过 F-Droid 的检查"**（`I7`④）且**⛔ 不叫"联网开关"**（`I7`⑤） |
| `B2-3` | **离线缓存 + 版本可失效** | 持久目录 + 版本化目录并存；`revoked` 与"不向前兼容"可使其失效（§4/§5）；**离线时照用本地版本** |
| `B2-4` | **硬内存上限 + 主动降级（不崩）** | 加载前检查可用内存与运行时上限；超限 ⇒ **不加载**、明示并降级回启发式（§5.2 存储/内存同类处置） |
| `B2-5` | **逐页 / 逐块流式** | 推理按页（PDF）或按块（表格区域）喂入；**单页失败不影响整篇**，失败页记一条警告（沿用既有可见性通道） |
| `B2-6` | **失败优雅降级回启发式** | 下载 / 验签 / 加载 / 推理**任一环失败** ⇒ 回落到启发式路径（`I5`），且**必须可见**（`.warnings`，卡 042 口径） |
