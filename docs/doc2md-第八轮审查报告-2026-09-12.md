## 1. 新确认 Bug（全部实测取证，按影响排序）

### 1.1 HTML 行内代码含反引号 → 输出 Markdown 结构破坏（P2）

**位置**：`src/html2md.js:72-76`（`codeFrag`）

**实测**（浏览器实测页用例 case1）：

| 输入 HTML | 当前输出 | 问题 |
|---|---|---|
| `<p>a <code>x\`y\`z</code> b</p>` | ``a `x`y`z` b`` | 渲染成「x」代码 +「y」代码 + 残尾 ``z` ``，内容面目全非 |

**根因**：`PRE` 块有动态围栏（`preBlock` 取内容最长反引号串 +1），行内 `codeFrag` 恒用单反引号包裹——内容自身含反引号时围栏被提前闭合。与三轮 §1.5（PRE 围栏）同族，但当时只修了块级。

**影响面**：技术文档里「讲 Markdown / shell 的文档」内嵌 `<code>` 含反引号是常见形态（本工具目标用户恰是技术写作者）；DOCX 路径 mammoth 对行内代码输出 `<code>`，同族暴露。

**修复**：`codeFrag` 按 `preBlock` 同款口径——围栏长度 = 内容最长反引号串 + 1（至少 1）；注意 CommonMark 细节：内容首/尾本身是反引号时，围栏内侧补一个空格（如内容 `` ` `` → `` ` ` ``）。

**回归用例**：契约组加「`<code>` 含反引号 → 双反引号围栏」断言（`.tmp/r8-html2md-test.html` case1 可直接转用例）。

### 1.2 xlsx 1904 日期系统被忽略 → 日期静默错 1462 天（P3）

**位置**：`src/xlsx.js:293-302`（`excelSerialToDate` 只按 1900 系统换算）；`parseSheetTags`（:82-95）只读 `<sheet>`，不读 `<workbookPr date1904="1"/>`

**实测**（Node 直跑 `xlsxConvert`，`.tmp/r8-xlsx-verify.mjs`）：构造 `date1904="1"` 与无该属性的最小 xlsx 各一份，同一 serial 38000 的日期样式单元格——**两者输出完全相同 `2004-01-14`**。1900 系统下 2004-01-14 正确；**1904 系统正确值 2008-01-15，错 1462 天（≈4 年）**，无任何 warning。

**影响面**：老 Mac Excel 产物 / 少数旧库存文件 / 部分第三方写入器。频率低，但失败形态是「静默给错数据」——与第五轮 §1.1（sheet 错位，当时定 P1）同一家族，因输入罕见降为 P3。

**修复**：`xlsxWorkbookMap` 顺带解析 `<workbookPr date1904>`；命中时 `excelSerialToDate` 基准改 `1904-01-01`（或 serial + 1462 折算到 1900 系统复用现逻辑）。`t="d"` ISO 字符串路径不受影响，无需动。

**回归用例**：合成 1904 工作簿断言 `2008-01-15`（`r8-xlsx-verify.mjs` 的 zip 构造器可直接转 gen-samples）。

### 1.3 `decodeXml` 链式替换双重解码 → 单元格文本静默损坏（P3）

**位置**：`src/xlsx.js:136-140`

**实测**（同上脚本）：单元格真实文本 `&lt;div&gt;标签&amp;&lt;实体`（XML 存储 `&amp;lt;div&amp;gt;标签&amp;amp;&amp;lt;实体`）→ 输出 `<div>标签&amp;<实体`——`&lt;`/`&gt;` 被二次解码（`&amp;` 因只出现一次替换链前序而侥幸正确）。

**根因**：五个 `.replace()` 串行执行，前一步的产物（`&lt;`）被后一步再次命中。正确语义应为单遍解码（XML 实体在原文中只解码一层）。

**影响面**：单元格 / sheet 名 / formatCode 含 HTML·XML 转义字面量的文本（技术表格、代码片段、网页数据导出）——静默内容损坏。`isoDateOnly`、`parseNumFmtCodes` 等同函数族。

**修复**：改单遍表驱动替换——一个 alternation 正则（`/&amp;|&quot;|&lt;|&gt;|&apos;|&#x([0-9a-fA-F]+);|&#(\d+);/g`）一次扫描，回调查表（数字实体换 `String.fromCodePoint`，顺带修 §1.6）。

### 1.4 HTML 转换泄漏 SVG / 表单控件 / canvas 文本（P3）

**位置**：`src/html2md.js:374-381`（`htmlToMarkdown` 的 remove 清单只有 `script, style, noscript, head, template`）

**实测**（浏览器实测页 case2-4）：

| 输入 | 当前输出 |
|---|---|
| `<p>前文<svg><title>logo</title><text>SVG里的文字</text></svg>后文</p>` | `前文logoSVG里的文字后文` |
| `<p>前文<select><option>选项A</option><option>选项B</option></select>后文</p>` | `前文选项A选项B后文` |
| `<p>前文<canvas>canvas后备文字</canvas>后文</p>` | `前文canvas后备文字后文` |

**影响面**：真实网页另存/粘贴转换时，图标 `<title>`（无障碍标签）、表单选项、canvas 后备文字全部漏进正文——噪音。DOCX 路径不受影响（mammoth 不产这些标签）；TXT 路径不解析 HTML。未知标签「子节点行内平铺」的兜底语义对未知**行内**标签合理，但这些是**无文本语义**的替换型/控件型元素，平铺即泄漏。

**修复**：remove 清单扩充 `svg, canvas, object, iframe, embed, audio, video, select, option, textarea`（`button`/`label` 可议——按钮文字有时是正文语义，建议拍板口径后定）。

### 1.5 列表项内表格的合并单元格告警丢失（P4）

**位置**：`src/html2md.js:236-247`（`blockChildToLines` 调 `blockOfEl(child, null)`——ctx 硬编码 null）

**实测**（case5）：顶层 `<table>` 含 colspan → warnings 1 条；**同样表格放进 `<li>` → 0 条**（内容本身仍正确，仅告警丢失）。

**修复**：`liToLines`/`liChildToLines`/`blockChildToLines` 增加 ctx 参数透传（调用方 `listElToMd` 已持有 ctx，链路现成）。

### 1.6 数字实体 > 0xFFFF 经 `fromCharCode` 截断（P4）

**位置**：`src/xlsx.js:139`

**实测**：`&#x1F600;emoji` → 输出 U+F600（私用区乱字符）+ `emoji`，应为 😀。`fromCharCode` 只取低 16 位。

**修复**：`String.fromCodePoint`（随 §1.3 单遍重写一并处理，无额外成本）。

## 3. 小项杂记（P4，按机会顺手）

1. `serialDateOrRaw`（`xlsx.js:374-379`）数字判定 `/^[+-]?[\d.]+$/` 不含科学计数法——Excel `<v>` 可存 `1.5E2` 形态，此时日期序列原样输出不换算。
2. `cjk.js` 标点类含 `%`+`：`「50 % 以上」合并成「50 %以上`」（R2 只并 `%↔CJK`，不并 `数字↔%`）——半合并观感，口径可议（顺带可考虑 `数字↔%` 也并入）。
3. `sniff.js:131-132` 同一注释行重复两行（纯清理）。

## 4. 已知项补充（不另立项；修 backlog A.2 §2.3「sheet XML 无解压护栏」时一并考虑）

`xlsxSelfParse`（`xlsx.js:456-464`）的 sharedStrings 4MB 护栏**在 `zipEntry` 全量 inflate 之后**才判定 `compSize`——对高压缩比字符串表（重复文本压缩比可达百倍）护栏无效，超限文件也先把内存花掉才 throw。修 sheet 护栏时建议给 `zipEntry` 增加「只查 compSize 不解压」的入口，把判定前移到 inflate 之前。
