# docs/spec-conformance-tests.md — 格式规范符合性测试清单（机制 + 对照表）

> 缘起（2026-09-10）：一次「外部视角」扫查发现若干**静默的规范符合性缺陷**（删除线丢失 / 表格列错位 / 编码探测窗口）。
> 本文把这类扫查固定成机制：**候选汇总 → 定位规范条款 → 产品级实测 → 登记 → 排期**。
> **纪律**：本文只写**规范条款 + 我们的实测行为**——不引任何第三方文本、编号或链接；外部线索的台账留在本地 `.私档/`（gitignore，永不入公开仓库）。

## 1. 机制（每轮五步）

| 步 | 动作 | 落点 |
|---|---|---|
| ① 汇总候选 | 三类来源：**格式规范条款**（OOXML / HTML Living Standard / GFM / PDF / WHATWG Encoding）、内部审查轮次、内部线索台账（本地） | 判断 |
| ② 定位规范 | 每条候选先找**规范原文条款**（哪条要求什么），据此写「期望行为」——期望必须可判定 | 规范文本 |
| ③ 产品级实测 | 造最小输入 → 宿主浏览器 `file://` 直开构建产物调测试挂钩（`window.__doc2md.*`），或 Node 直跑纯函数；**不靠读代码猜** | `browser_*` / `node` |
| ④ 登记 | 填 §2 表（规范条款 → 期望 → 实测 → 处置）：不符走**先红后绿**；符合则**补断言锁死** | 本文 + `tests/CONTRACT.md` |
| ⑤ 节奏 | 与审查轮次同频（每轮审查 / 每批收尾）；不符项进 `docs/HANDOFF-主开发线.md` backlog 排期 | HANDOFF |

### 2.1 修复记录（S2，2026-09-10）

- **规范依据**：HTML `<s>` / `<del>` / `<strike>` = 删除语义；GFM 删除线扩展 = `~~…~~`；OOXML `w:strike` 同义。
- **契约先红**（`435af14`）：新增**契约组 S**（S2-1..S2-4 html2md 快照 + S2-5 DOCX 端到端，页内 fflate 造最小 docx）→ 先红实测 **6/6 失败**（`a struck b` vs 期望 `a ~~struck~~ b` 等）。
- **实现**（`1a6c581`）：`src/html2md.js` `FRAG_TAGS` 增 `S`/`DEL`/`STRIKE` → `strikeFrag`（复用 `emphasisFrag` 包 `~~`，空内容不产出片段）。
- **后绿**：组 S **6/6 通过**；全量契约 **159/159 pass / 0 fail**（36.2s，零回归）；产物 `2b2a0eb`（index.html 109,076 B / SHA `5CC3755E…`）。
- **DOCX 路径同源**：mammoth 把 `w:strike` 映射为 `<s>`（源码实证），与 HTML 走同一分支 → 一处修复覆盖两类输入。

### 2.2 修复记录（S3，2026-09-10）

- **拍板（用户 2026-09-10）**：① XLSX 一律按 `r` 列号归位（乱序也放对列），`r` 缺失才回落文档序；② `colspan` = **内容放首列、其余补空**（GFM 无合并结构，补空保持列位置正确且不重复膨胀）。
- **契约先红**（`3c78ba2`）：组 S 增 S3-1..S3-5（XLSX 稀疏 / XLSX 乱序 / HTML colspan / colspan 表头一致性 + 告警 / colspan 巨值封顶）→ 先红实测 **5/5 失败**（如 `| A2 | C2 |  |` vs 期望 `| A2 |  | C2 |`）。
- **实现**：
  - S3-①（`5dd4478`）：`src/xlsx.js` `parseCellAttrs`/`parseCellAt` 增 `r` 字段 → `rowToTexts` 按列号放置（缺列补空、乱序归位、无 `r` 或超 XLSX 列上限 16384 回落文档序）；新增 `colIndexOfRef` / `refLetterValue`。
  - S3-②（`b9002da`）：`src/html2md.js` 新增 `spanOf`（rowspan/colspan 解析，上限 `MAX_COLSPAN = 100`）→ `rowCells` 按 colspan 追加空列；`cellToMd` 改用 `spanOf` 判定「合并单元格」告警（既有文案不变）。
- **后绿**：组 S S3 **5/5 通过**；全量 **165/165 pass / 0 fail**（38.1s，零回归）；产物 `a58b067`（index.html 110,021 B / SHA `302AA424…73B50B4B`）。
- **样例无 `r` 是零回归的关键**：仓库 gen 产物样例的 `<c>` 不带 `r` → 回落文档序 = 既有行为（既有快照不动，实测零回归）。
- **顺带修掉一个「假绿」**：`tools/metrics.mjs` 原来在 jscpd `spawnSync` 失败时读 `.tmp/` 里**上一次的旧报告** → 沙箱内重复率长期显示 4%（真值 8.86–9.37%）。现改为「先删旧报告 + 仅 jscpd 成功才读，否则标 N/A」（`c28fa5c`）。教训：**度量工具的"读旧值"路径 = 假绿来源**，与业务代码同等对待。

### 2.3 修复记录（S4，2026-09-11）

- **规范依据**：WHATWG Encoding —— 编码探测启发式不应只依赖文件开头若干字节。
- **拍板（用户 2026-09-11）**：**口径 A 全篇判定** —— UTF-8 `fatal` 快检先行（合法即返回，零额外成本），非法才做全篇 U+FFFD 计数；保留「≥2 个 U+FFFD 才考虑回退」阈值与「gb18030 替换符更少」比较；`<meta charset>` 扫描窗口语义**不动**（避免「正文里提到 gbk」误命中，规范本身也只认前 1024 B）。
- **契约先红**（`a53eaba`）：组 S 续号 S4-1..S4-4 → 官方先红实测 **S4-1/S4-2 红**（S4-3 保真、S4-4 零额外成本探针按设计绿）。
- **实现**（`38e623f`）：`src/sniff.js` `decodeText` 全篇化（+17/−10）—— `tryUtf8Strict` 快检 + 全篇 `countFffd` 比较。
- **后绿**：组 S S4 **4/4 通过**；全量 **174/174 pass / 0 fail（46.6s，零回归）**；产物 `885b548`（index.html 111,449 B / SHA `A0D40639…B28977`）。

### 2.4 修复记录（S5，2026-09-11）

- **规范依据**：OOXML 双删除线 `w:dstrike` 语义同单删除线 = 删除。
- **拍板（用户 2026-09-11）**：取候选 ① —— docx 预处理把自闭合 `w:dstrike`（无 `w:val` 或 `w:val` 非 false/0/off）归一为 `w:strike`；`w:val=false/0/off` 原样保留（不得误标）；原始字节不含 `w:dstrike` 时**零额外解包/改写**。

### 2.6 修复记录（第八轮审查 · 规范相关项，2026-09-12）

- **§1.1 行内代码围栏（CommonMark）**：`<code>` 内容含反引号时恒用单反引号包裹 → 围栏提前闭合、结构破坏。修：围栏长度 = 内容最长反引号串 + 1（至少 1），**内容首/尾为反引号时围栏内侧补一个空格**（`codeFrag`，与 `preBlock` 同口径）。组 K2 k2-1..k2-6。
- **§1.3/§1.6 XML 实体解码**：五步链式 `replace` 使前一步产物被后一步再次命中（`&amp;lt;` → `<`，多解一层）；数字实体用 `fromCharCode` 截断代理对。修：单遍 alternation + 查表 + `String.fromCodePoint`（越界码点保留原文、不抛 RangeError）。组 G7 g7-6/g7-7。

## 3. 待拍板点（首轮）

1. **删除线范围（S2 已修，剩 CSS 分支）**：`<s>/<del>/<strike>` → `~~` 已实现（`1a6c581`）。CSS `text-decoration: line-through` 是否一起支持（HTML 输入常见，约 +5 行解析）——**仍待拍板**。

3. **colspan 语义（S3-② 已定案实现）**：**内容放首列、其余补空**（用户 2026-09-10 拍板）；列数上限 `MAX_COLSPAN = 100`（防巨值撑爆单行）——上限值如需调整属新口径。
4. ~~**编码窗口**~~ ✅ **已定案（2026-09-11 用户拍板口径 A）**：改为**全篇判定**（UTF-8 `fatal` 快检 + 全篇 U+FFFD 计数），`<meta charset>` 扫描窗口语义不动；实测零回归（F 组 F1–F7 全绿），见 §2.3。
5. ~~**双删除线 `w:dstrike`（S5）**~~ ✅ **已定案并实现（2026-09-11）**：取候选 ①（docx 预处理归一），并加 `w:val` 关闭值边界（false/0/off 不归一）与零改写快路径；见 §2.4。
6. **S4 门的小基数边界（C4/C10/C13）**：非 ASCII 基数很小时（≤10×FFFD）门会放行、输出被 gb18030 改写——**t9 前后行为一致**，收紧须不破坏 C1/C2/C8 判别（GBK 长文 / ASCII+GBK 尾 / 真 GBK）。**待拍板**。
7. **S5 后续加固（t13 的 3 条 low）**：注释/CDATA 内未闭合 dstrike 跨边界配对（自 S5 既有）、dstrike 非法嵌套内层漏改、畸形输入配对分支 O(n²)——建议并入下一轮 S5 加固批。
8. **cjk `%` 半合并（第八轮 §3.2，登记待拍板）**：`「50 % 以上」→「50 %以上」`（R2 只并 `%↔CJK`，不并 `数字↔%`）——是否把 `数字↔%` 一并纳入属口径问题，**未动**。
9. **脏数字实体边界（第八轮交叉审查观察）**：`&#xD800;`（孤立代理）与 `&#0;` 现按码点直出（与修复前一致），建议后续按 HTML 规范映射 U+FFFD。
