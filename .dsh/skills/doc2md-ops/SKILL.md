# doc2md 执行线 · 日常作业（doc2md-ops）

> ⛔ **本技能不管「卡怎么执行」** —— 那是同工作区 `task-execution` 的事（定基线 → 先红 → 实现 → 门禁 → 证据 → 回写 → 报告）。
> 这里只管**卡之外的作业面**，以及**每件事的唯一权威源在哪**。

## 0. 一句话

**先找权威源，再动手；能做成机制的就别只写进文档；凡「删 / 挪 / 发布」先列命令等人点头。**

## 1. 发布与收尾（入口 = `.私档/工具/发布流程.ps1`）

- ⭐ **不要手打 git/gh 序列** —— 用工具（默认 dry-run，`-Yes` 才真跑）：
  `pwsh -File .私档\工具\发布流程.ps1 -Branch <分支> -Title <标题> -BodyFile <正文.md> [-ExpectCommits N] -Yes`
- 它覆盖：push 分支 → 建 PR → **等 checks（内置「先探测再 watch」，治「PR 刚建、GitHub 还没登记 check suite」的假失败）** → squash 合并 → fetch → **`分支收尾.ps1 -Apply -SyncMain`** → 收尾。
- ⚠️ **`main` 受规则集保护**：`main-privacy-gate` = `deletion` + `required_status_checks(checks)` ⇒ **直推会被拒**（`GH013 … Required status check "checks" is expected`）；**tag 侧无保护**。
- ⚠️⭐ **tag 必须打在【最终落地的提交】上**：PR 走 squash ⇒ 落地 SHA ≠ 分支 head ⇒ **顺序 = 先合并、再打 tag**。（v0.1.11 实证：先打的 tag 落在 PR head 上 —— 树虽相同，但「tag 不是 main 的祖先」，属已知形态。）
- 发版体例与步骤：`docs/RELEASE.md`（历史节体例）· `docs/RELEASE-CHECKLIST.md`（步骤）· `.私档/工具/发布流程-纪律与模板.md`（**工具的唯一权威源**，§一~§十五）。
- ⭐ **发版前必跑**：四处版本同步（`package.json` · `package-lock.json` L3/L9 · `src/template.html` 页脚 · **重建 `index.html`**）→ `node tools/apk-version-check.mjs`（release + debug 两路）→ **推 tag 之前** `node tools/check-pages-allowlist.mjs`。
- 同步判据（`分支收尾.ps1 -SyncMain`）：安全 = **本地领先 0 条**（落后 ⇒ 复位只跟进）或**树相同**；算不出 ⇒ **throw**（⛔ 不 reset）。

## 2. LAN 交换出包（git bundle → 手机 / Linux 侧）

- 位置：`.私档/lan-git/`（`exchange-www` = HTTP 服务根 · `.curl-auth` / `.exchange-token` = 口令文件，⛔ **不读、不打印**）。
- 命名体例：`orders-<日期>-<内容>.bundle` + 同名 `.bundle.sha256`（**一行纯哈希**）+ 同名 `-手机侧怎么用.txt`。
- 两类包：**快照（全量，无 prerequisite）** / **增量（`<基点>..main`，带 prerequisite）**。增量必须写明**基点**，说明文件里给全"若你只到某一版 ⇒ 先套哪一个"的链条。
- ⛔ **不进包的口径**（照抄快照提交信息）：`lan-git/` 自身（递归排除）+ `.私档/传输-手机-*` 两个大夹具；**保留快照自带的 `.gitattributes`（内容 `* -text`，关掉换行转换）**。
- 出包步骤（⛔ 世系别断）：`clone 最后一个快照 bundle` → `fetch + merge --ff-only 后续增量` → 让工作树与当前 `.私档` 一致（`robocopy /MIR`，**必须 `/XD lan-git 传输-* .git`** —— ⚠️ 漏 `.git` 会删掉仓、漏 `.gitattributes` 会引入 CRLF 转换）→ 提交（身份 `doc2md-lan <lan@local>`，⛔ 不用真实邮箱）→ `git bundle create <out> <基点>..main` → 校验 → 落 `.sha256` → 写「怎么用」。
- 校验：`git bundle verify <out>` —— ⚠️ **必须 `-C` 到【有世系】的那个仓**，否则只会报 `lacks these prerequisite commits`（在错误的仓里跑 = 假红）。
- 服务：`.私档/工具/启动交换服务.cmd`（8099 · **HTTP Basic 口令**，口令 = `.exchange-token` 文件内容）。

## 3. 隐私门禁（`tools/privacy-gate.mjs`）读写纪律

- 模式/退出码：`--staged`（pre-commit）· `--stdin-refs`（pre-push）· `--range A..B`（CI）· `--all`（只报告）；`0` 通过 · `1` 命中 · `2` fail-closed（读不到范围，**或 `--range` 是空区间**）。
- ⭐ **提交前必跑 `--staged`** —— `--no-verify` 绕的是「钩子能否启动」，⛔ 不是「判据」；**收尾再复跑一次**（回执/报告自己也是新增行）。
- ⛔⭐ **「复述」是最危险的动作**：讲规则、写修法说明、复述卡面给的特征串、把合成值写进测试或注释 —— 都会把值带回新增行 ✗。
  ⇒ 只写 **类别 / 规则名 / 段结构**；确需在代码里出现合成值 ⇒ **运行期拼装**（如 `['a','b'].join('@')`）+ 注释只留形状描述。
- 空区间 = **一个提交都没扫到** ⇒ ⛔ 不许报「通过」（已在 `guard-selftest` 有常驻回归四条）。

## 4. 临时区（`.tmp/`）卫生

- 口径：`.tmp` **只活这一轮**（见 `~/.dsh/落盘规范.md`）；收尾必须列「本轮新增文件及去向」。配套工具 **临时区体检** 就是把这个动作变成看得见的输出。
- 体检判据（三条分清）：① **可再生** —— 工具每次运行会重建它（如 OCR 语言目录、测量脚本的 stage 目录）；② **零 tracked 引用** —— `git grep -c <名字> -- . ':(exclude)docs/任务台账.md'` ⇒ 0；③ **工具在用** —— 被 `tools/*.mjs` 当**输出目录**引用时，要看它是不是**输入**。
- ⭐ **搬家再删**：临时区里凡是**唯一副本**（例：私有 bundle 的世系仓）⇒ 先固化到 `.私档/` 再删。
- ⛔ 删除一律**先列清单等人点头**（铁律 2）；本技能的工具**只报告、不删**。

## 5. 记忆维护（mneme）

- **默认手动**：先提议（一句话说清「记什么 + 为什么跨会话有用」）⇒ 用户点头 ⇒ 才写。
- ⭐ **同族优先合并**（⛔ 不新建近似条目）；**更新时保留原文，只追加**（呼应本仓「只更正、不抹掉」）。
- ⭐ **写完双向验证**：搜一个**只在原文**的词 + 一个**只在新增**的词 ⇒ 两者都命中，才证明是"追加"而不是"覆盖"。
- 只记**跨项目仍有用**的：用户偏好 / 工程约束 / 踩过的坑（含根因）/ 全局决策；⛔ 不记项目进度与会话流水。

## 6. 交接口径（状态只认权威源）

- 唯一权威源：`docs/HANDOFF-主开发线.md` 的**生成块**（由 `BASELINE.json` 生成）· `docs/BASELINE.json` · `docs/RELEASE-CHECKLIST.md` §3/§4 ⇒ ⛔ 别在别处缓存现值。
- **过程档案不进公开仓**：新写的回执 / 停工报告 / 交接单 / 审查记录一律落 `.私档/卡/c<NNN>/`；⚠️ 向**已跟踪文件追加**过程档案**等同新写**（点名 `DEV-NOTES` 的收录边界）；**台账只留索引行**（正文搬走、通道必须留下）。
- 卡收尾的固定动作：**回执（必带 坑 / 根因 / 防再犯）→ 台账索引行 → 发布前审查落盘 → 断言过户 → 临时区体检**。
- ⚠️ 改了 `docs/BASELINE.json` ⇒ 必跑 `node tools/gen-handoff-baseline.mjs`（否则 CI 第 18 步红），且 `baseline-check` 的 `released` 节点是**从 tag blob 现算** ⇒ tag 不存在时改它**必红**。

## 7. 交接与待办放哪（新会话开工先看这里）

- ⭐ **每次长会话收工** ⇒ 在 `.私档/` 写一份 **`下一会话-<日期>.md`**，内容要**自包含**：**基线（HEAD / 分支 / 未推数）** · **本会话已完成（⛔ 明确标"不用重做"）** · **待办（按建议顺序，每条先列命令或清单等点头）** · **口径速查** · **本会话踩过的坑**。
- ⭐ **新会话开工**：读 `.私档/` 下**最新的** `下一会话-*.md` ⇒ 再按 `task-execution` 进卡流程。⛔ 别指望"上下文还在"。
- ⚠️ **本工作区的技能是入库的**（`.dsh/skills/<name>/SKILL.md` 走 PR —— 先例 `skill(task-execution) v1.2`）⇒ 新建 / 修改技能要按发布流程提交；⛔ 别让它长期 **untracked**（会把工作树弄脏 ⇒ `发布流程.ps1` 的"工作树必须干净"入口检查会**拒跑**）。
- ⚠️ **改 SKILL.md 的 frontmatter 后必须验证两件**：① 重读并确认引号成对（双引号标量内 ⛔ 不放半角引号）；② **技能是否仍在技能目录里** —— 坏 frontmatter 只会被**静默跳过**、零报错（本仓已踩过）。
